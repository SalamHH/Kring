# M0 — backend spike: ingest + geocode + DB

Spec: [`docs/stedSafe-spec.md`](../stedSafe-spec.md) §8, §9, §14, Appendix C.
Definition of done (§14): live Oslo ingestion running; Appendix C fixtures green; interview notes summarised.

**Settings for this milestone:**
- **Scope:** Oslo (0301) and Akershus (county 32). The allowed set is a setting.
- **Where it runs:** locally only; Render comes in M1.
- **Local setup:** Homebrew `postgresql@17` and `postgis`, plus `uv` pinning Python 3.12. No Docker.
- **Out of scope:** the REST API (including `/v1/health`), matching, push, digest and mobile.
- **Interviews:** your track; the summary goes in `docs/interviews/`.

Each step is one commit and ends with `uv run pytest` and `uv run ruff check` passing.

- [x] **7. Ingestor**
  - Paginate with the §8.3 stop rule, dedupe, and upsert events and messages.
  - New thread: geocode, then classify.
  - Updated thread: re-geocode by the §8.3 rule.
  - Politiloggen backoff of 1–16 s; log an ERROR after 10 min with no successful poll; update `ingest_state`.
  - *Verify:* integration tests on recorded pages:
    - Running the same cycle twice creates no duplicates and makes no new geocode calls.
    - A new message is appended.
    - A changed area or an imprecise tier triggers a re-geocode.
    - A stale poll logs an ERROR.
