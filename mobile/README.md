# Kring mobile

Expo (SDK 58, TypeScript, expo-router). Spec: [`../docs/kring-spec.md`](../docs/kring-spec.md) §7 and §8. Plan: [`../docs/plans/m1.md`](../docs/plans/m1.md).

MapLibre and push need native code, so the app runs as a **development build**, not in Expo Go. The `ios/` and `android/` folders are generated by `expo prebuild` and are not committed. Change native settings in `app.json` instead.

## Setup (macOS)

- Node 24 (Homebrew `node@24`).
- Xcode with an iOS Simulator runtime, and CocoaPods (`brew install cocoapods`).
- Android Studio with an emulator that has a Google Play system image, plus JDK 17 (`brew install --cask zulu@17`). `ANDROID_HOME` and `JAVA_HOME` set in `~/.zshrc`.
- [Maestro](https://docs.maestro.dev) for the end-to-end flows, from its own Homebrew tap. The plain `maestro` cask is a different product.

```bash
brew tap mobile-dev-inc/tap && brew install mobile-dev-inc/tap/maestro
```

```bash
npm install
```

## Run

Start the local API first (see [`../backend/README.md`](../backend/README.md)). In development the app talks to it at `http://localhost:8000`, or `http://10.0.2.2:8000` from the Android emulator. Set `EXPO_PUBLIC_API_URL` in `.env.local` to use another API, such as `https://kring-api.onrender.com`, and restart Metro with `--clear`. The app then registers a new device on that API, and again when you switch back.

```bash
npm run ios        # builds, installs on the iOS Simulator and starts Metro
```

```bash
npm run android    # the same for the running Android emulator
```

On an Android 17 (API 37) emulator, the development build asks to «find, connect to, and determine the relative position of nearby devices». That is the new local-network permission, which the emulator needs to reach Metro and the API at `10.0.2.2`. Answer **Allow**. If it was refused, the app shows a blank screen; grant it with `adb shell pm grant no.kring.app android.permission.ACCESS_LOCAL_NETWORK`. Only React Native's debug manifest declares this permission, so store builds don't ask for it.

After the first build, only JavaScript changes need no rebuild: `npm start` and press `i` or `a`. A new native package or an `app.json` change needs `npm run ios` / `npm run android` again.

Don't start Metro with `CI=1`: it turns off Fast Refresh and the typed-routes generation that `tsc` needs for `router.push('/place/new')`.

## Check

```bash
npx tsc --noEmit && npx expo lint && npx jest
```

End-to-end on the iOS Simulator, with the dev build installed and Metro and the local API running (see Run):

```bash
npm run test:e2e
```

- **Component tests** (`__tests__/*.test.tsx`, React Native Testing Library) render a screen in Node with the map, router, API session and push prompt replaced. They check what the screen shows and what it sends, so most of a screen's behaviour is covered without a simulator.
- **Maestro flows** (`.maestro/`) tap through the real app on the simulator and report each step as text. `open-dev-build.yaml` (tag `helper`) opens the dev build on Metro's bundle, and the other flows start with it. Each flow cleans up the data it creates. On a failure, Maestro saves its logs and a screenshot under `~/.maestro/tests/`.
- Maestro can't type «æøå» reliably, so flows search with plain-ASCII queries such as «Grensen 10».
- The script turns Maestro's usage analytics off (`MAESTRO_CLI_NO_ANALYTICS`).

- `__tests__/tokens.test.ts` and `strings.test.ts` read the spec itself (§7.1 and Appendix B), so a change on one side only fails here.
- `__tests__/api.test.ts` runs the API client, device registration and the place, search and preview calls against a mock HTTP server.
- `__tests__/Home.test.tsx` and `home.test.ts` cover Hjem: every status row, «N ny», the district row, the poll status, navigation and the opened store.
- `__tests__/PlaceEditor.test.tsx` covers Nytt sted: the defaults, the debounced search, templates, the small-radius note, the coverage note, saving, push only after a save with push on, errors, editing (only changed fields) and deleting.
- `__tests__/places.test.ts` checks the templates against spec §6.1 and the categories against Appendix B, and covers the radius label, the small-radius note, time-window labels, the preview text and the edit diff.

| `components/PlaceEditor.tsx` | Nytt sted (F1–F3): search, type and category chips, name, map, radius, preview, «Når», push, save and delete. |

| `lib/placeHooks.ts` | The debounced search and the preview, which ignore answers to questions no longer asked. |
| `lib/api.ts` | API client (§8.6). Errors become `ApiError` with the API's `error` code. |

| `lib/push.ts`, `lib/bootstrap.ts` | Push permission and the Expo push token, sent with `PUT /v1/devices/me`; refreshed when the app comes back to the foreground. The OS prompt is shown only by `askForPush`, after a place is saved. |

## Push

The EAS project is `@salamhh/kring`; its ID is in `app.json` under `extra.eas.projectId`, and the Expo push token is requested with it.

- **When the app asks:** not at launch, but right after a place with push on is saved (spec §8.7, decided 2026-11-15). Each launch only reads the permission: if it's granted, the token is sent; otherwise the token is cleared on the server.
- **To see the prompt again** on the simulator, reinstall the app (the Keychain keeps the device): `xcrun simctl uninstall booted no.kring.app`, then `xcrun simctl install booted <DerivedData>/Build/Products/Debug-iphonesimulator/Kring.app`.
- **iOS Simulator:** gets an Expo push token, which ends up on the device row.
- **Android:** needs Firebase. Until `google-services.json` is in the app config, the app logs `Default FirebaseApp is not initialized` and registers without a token.
- **Sending:** an actual push needs APNs and FCM credentials on the EAS project (M1 step 12).
